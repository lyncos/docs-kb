### Description

Passing a custom `User-Agent` header to the sHTTP transport, e.g. [here](https://github.com/modelcontextprotocol/python-sdk/blob/27279bc157cbc03f7fe7758fd55a4b34c5652f42/examples/clients/simple-auth-client/mcp_simple_auth_client/main.py#L214-L220) does not result in auth flow requests including that user agent. There also does not appear to be any way to customize this behavior externally to the SDK itself.

In particular, this becomes a problem when working with AWS WAF, as one of its [baseline rules](https://docs.aws.amazon.com/waf/latest/developerguide/aws-managed-rule-groups-baseline.html#aws-managed-rule-groups-baseline-crs) is to require all requests to include a `User-Agent` header, to filter out low-grade spam.

I am currently recommending to internal teams that they disable this rule for the time being, but this is not a great solution for them, as it means removing an application guardrail to work around an SDK limitation.

### Example Code

``` notranslate
print("📡 Opening StreamableHTTP transport connection with auth...")
async with streamablehttp_client(
    url=self.server_url,
    auth=oauth_auth,
    timeout=timedelta(seconds=60),
    headers={
        "User-Agent": "mcp-python-sdk/0.1.0",
    },
) as (read_stream, write_stream, get_session_id):
    await self._run_session(read_stream, write_stream, get_session_id)
```
