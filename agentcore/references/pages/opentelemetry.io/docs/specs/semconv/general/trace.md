# Trace semantic conventions

**Status**: [Mixed](/docs/specs/otel/document-status/)

In OpenTelemetry spans can be created freely and it’s up to the implementer to annotate them with attributes specific to the represented operation. Spans represent specific operations in and between systems. Some of these operations represent calls that use well-known protocols like HTTP or database calls. Depending on the protocol and the type of operation, additional information is needed to represent and analyze a span correctly in monitoring systems. It is also important to unify how this attribution is made in different languages. This way, the operator will not need to learn specifics of a language and telemetry collected from polyglot (multi-language) microservice environments can still be easily correlated and cross-analyzed.

The following semantic conventions for spans are defined:

- **[General](/docs/specs/semconv/general/attributes/): General semantic attributes that may be used in describing different kinds of operations.**
- [Compatibility](/docs/specs/semconv/general/trace-compatibility/): For spans generated by compatibility components, e.g. OpenTracing Shim layer.
- [CloudEvents](/docs/specs/semconv/cloudevents/): Semantic Conventions for the CloudEvents spans.
- [Cloud Providers](/docs/specs/semconv/cloud-providers/): Semantic Conventions for cloud providers spans.
- [Database](/docs/specs/semconv/db/database-spans/): For SQL and NoSQL client call spans.
- [Exceptions](/docs/specs/semconv/exceptions/exceptions-spans/): For recording exceptions associated with a span.
- [FaaS](/docs/specs/semconv/faas/faas-spans/): For [Function as a Service](https://wikipedia.org/wiki/Function_as_a_service) (e.g., AWS Lambda) spans.
- [HTTP](/docs/specs/semconv/http/http-spans/): For HTTP client and server spans.
- [Messaging](/docs/specs/semconv/messaging/messaging-spans/): For messaging systems (queues, publish/subscribe, etc.) spans.
- [Object Stores](/docs/specs/semconv/object-stores/): Semantic Conventions for object stores spans.
- [RPC/RMI](/docs/specs/semconv/rpc/rpc-spans/): For remote procedure call (e.g., gRPC) spans.

Apart from semantic conventions for traces, [metrics](/docs/specs/semconv/general/metrics/), [logs](/docs/specs/semconv/general/logs/), and [events](/docs/specs/semconv/general/events/), OpenTelemetry also defines the concept of overarching [Resources](https://github.com/open-telemetry/opentelemetry-specification/blob/v1.59.0/specification/resource/sdk.md) with their own [Resource Semantic Conventions](/docs/specs/semconv/resource/).
